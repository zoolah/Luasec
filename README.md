# Luasec

Luasec is a self-hosted Luau/Roblox script protection and licensing platform built for developers who want to protect code inside a script-executor environment such as the executors listed on [weao.xyz](https://weao.xyz).

The goal is to gate execution of Luau code in an execution environment where users may attempt to inspect, modify, or replay scripts inside executors that expose the runtime.

This project is designed as a public-facing starter template for developers who want to build their own licensing system.

It is NOT a plug and play solution. It will require lots of setup and work.

## What it does

Luasec lets a developer:

- Create a script entry in the dashboard
- Generate access keys and assign them to users
- Distribute the loader and license flow through Discord or the web dashboard
- Bind access to hardware identifiers and user metadata
- Protect Luau/Roblox code so it only runs when a valid key and valid session are present
- Run a protected script client that validates authentication before executing code
- Manage script users, whitelists, key redemption, and blacklist events through the admin panel

Typical workflow:

1. Script owner uploads or registers a protected Luau/Roblox script
2. The dashboard generates keys and metadata
3. A user receives their key via Discord or the website
4. The user executes their loader along with their key
5. The Roblox client loader authenticates against the server 
6. The server verifies the user, key, and HWID conditions
7. The protected Luau code is only executed after validation passes

## Architecture overview

- Express app server with session/auth routing in [main.js](main.js)
- Discord OAuth login and bot initialization in [bot.js](bot.js)
- MongoDB data layer in [db/mongo.js](db/mongo.js)
- Auth and dashboard routes in [routes/mainRouter.js](routes/mainRouter.js) and [routes/authRouter.js](routes/authRouter.js)
- API and CDN routes in [routes/apiRouter.js](routes/apiRouter.js) and [routes/cdnRouter.js](routes/cdnRouter.js)
- Lua client loader in [client/loader.lua](client/loader.lua) and [client/main.lua](client/main.lua)
- Frontend dashboard templates in [frontend/](frontend)
- Discord command and interaction logic in [discord/](discord)
- Uses the [https://wynfuscate.com/](wynfuscator obfuscator) as a core component 


## Prerequisites

- Node.js 18+
- MongoDB instance or Atlas cluster
- Discord developer app + bot token
- Cloudflare Zero Trust / tunnel access if you want a public domain
- Wynfuscate API key if you are using the obfuscation flow
- A custom domain for your project

## Quick start

1. Install dependencies:
   ```bash
   npm install
   ```

2. Create your local environment file:
   ```bash
   copy .env.example .env
   ```
   Then edit `.env` with your real values.

3. Create the Cloudflare config:
   ```bash
   copy config.example.yml config.yml
   ```
   Update the hostnames to match your domain and tunnel ID.

4. Update your tunnel token in `tunnel.bat` or your deployment script.

5. Start the project:
   ```bat
   start.bat
   ```

## Environment variables

The app expects the following variables in `.env`:

```env
TOKEN=your_discord_bot_token
CLIENT_ID=your_discord_application_id
CLIENT_SECRET=your_discord_client_secret
BASE_URL=https://app.yourdomain.com
MONGO_URI=mongodb://127.0.0.1:27017/luasec
MONGO_DB=luasec
SECRET=replace_with_a_long_random_secret
WYN_API_KEY=your_wynfuscate_api_key
PORT=3000
```

## Cloudflare tunnel setup

Use Cloudflare Zero Trust tunnels if you want to expose the project through your own domain.

Important: Make sure `cloudflared.exe` is added to your system PATH before running the tunnel command. If it is not on PATH, the tunnel command will fail.

To setup your tunnel:

1. Create a tunnel in Cloudflare Zero Trust
2. Download/install `cloudflared` and add `cloudflared.exe` to your PATH
3. Grab the tunnel token and put it in your tunnel launch command 
4. Add DNS records for:
   - `app.yourdomain.com`
   - `auth.yourdomain.com`
   - `api.yourdomain.com`
   - `docs.yourdomain.com`
   - `cdn.yourdomain.com`
5. Point each to the tunnel hostname generated by Cloudflare

The configured hostnames should route to `http://localhost:3000` inside the tunnel config.
